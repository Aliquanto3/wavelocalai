# Codebase Audit: full run, seven pillars

The measurement core is sound (timed metrics come from llama-server's own `timings`, every row passes the row contract, locks are hashed, suites pass at 96.6% / 83.1% line coverage), but the comparison layer that turns rows into published verdicts and dense-vs-MoE claims has three correctness gaps that surface exactly on the three-machine campaign.

- **Date**: 2026_09_22
- **Scope**: `src/wave_local_ai_v2/` (43 modules), `frontend/src/`, `scripts/`, `.github/workflows/ci.yml`, `tests/`, against `aidd_docs/GUIDELINES.md` and the memory bank. Audited on `feat/dense-moe-view` with the uncommitted comparison-view changes (`read_model.py`, `frontend/src/views/comparison/`, `index.css`) as-is; rows touching that code are marked *(in-flight)*.
- **Health**: fair
- **Findings**: 3 critical, 27 warning, 33 minor

Health: `good` = no critical findings; `fair` = critical findings exist but are isolated and addressable; `poor` = systemic or widespread critical findings.

Ranking rule for this run: what threatens the publication objective (defensible numbers, reproducibility on three machines) ranks above style, within each severity band. Pillar files (`code-quality.md`, `architecture.md`, `security.md`, `dependencies.md`, `performance.md`, `tests.md`, `ui.md`) hold the full evidence per row; this report merges and dedupes them. All three 🔴 were re-read against the source by the orchestrator, not only the pillar agents.
