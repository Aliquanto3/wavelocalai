### Modèles : reranker (story 5.5)

Ajouts de la story 5.5 à ce fichier, dans leur propre sous-section. **Amendé par la story 9.5** (décision D-R6, 2026-10-21) : fastembed est une dépendance de base, plus un extra ; `GET /api/rag/settings` ne porte donc plus `extra_installed`. Le reranker reste le seul modèle qui ne vient pas d'Ollama : un modèle fastembed lu dans le `cache_dir` du dossier de données (`<données>/models/fastembed`), jamais téléchargé par une recherche (`local_files_only=True`).

- `POST /api/models/reranker/pull` (écriture, `Origin` contrôlée, sans corps) rend `{run_id}` aussitôt ; il crée un run racine `pull` (le seul téléchargement du reranker, AD-17 ; AD-14 : un seul `pull` à la fois, modèle d'Ollama ou reranker) dont la progression se lit par `GET /api/runs/{id}/events`. `runs.params = {tag, reranker: true}`, `models = [modèle du reranker]`. `409 run_busy` (`detail.run_id` : l'installation en cours, que l'écran rejoint) ; `422 invalid_request` si le modèle est déjà installé. Le téléchargement tourne dans un processus à part (`python -m wavelocalai.rag.rerank_fetch`, `disable_telemetry()` avant l'import de fastembed) que l'annulation tue : `POST /api/runs/{id}/cancel` rend `cancelled`.
- Événement `pull_progress` : la forme de la 5.3, avec `reranker: true` et `tag` = nom du modèle fastembed (`jinaai/jina-reranker-v2-base-multilingual` par défaut, `rag.reranker_model`). `received_bytes` est la taille du dossier du modèle dans le cache (fastembed ne rend aucune progression), `total_bytes` la taille annoncée par fastembed pour ce modèle (`0` si inconnue, `percent` est alors `null`) ; `phase` : `preparing`, `downloading`, `verifying` (reçu au plus à 99 % du total, tant que le chargement de vérification tourne ; le dernier événement est à 100 %). Au plus un par seconde.
- Fin du run : `ok` quand le modèle est téléchargé et chargé une fois pour vérification ; l'état du reranker est alors relu **avant** `run_ended` (`GET /api/rag/settings` dit `available: true`, la recherche suivante reclasse sans redémarrage). `cancelled` ou `error` : le dossier du modèle est retiré s'il n'existait pas avant le run (« non installé » reste vrai) ; `error` porte `pull_failed` avec `detail.cause: "reranker_failed"` et `detail.technical` (dernière ligne de l'erreur du processus) : « Le reranker {modèle} n'a pas pu être installé. », action « Vérifiez la connexion au réseau et l'espace disque, puis relancez l'installation. La recherche reste sans reclassement en attendant. »
- `GET /api/rag/settings` : `reranker` porte `{model, available, reason}` ; actif dès `uv sync` seul (story 9.5).
- Routes de test (`WAVELOCALAI_TESTING`) : `POST /api/test/reranker-install {mode: ok|fail|hang, total_bytes, steps, step_delay_s, interval_s, reason}` remplace le téléchargement par un faux (octets simulés) ; `GET` rend `{downloads}`.
