## `GET /api/rag/settings` (et la vue rendue par `PUT`)

- Nouveau champ `verify_min_params_b` (nombre) : le nombre de milliards de paramètres actifs en dessous duquel la stratégie vérifiée (`self_rag`) est peu fiable avec un modèle local, parce que le modèle y juge lui-même la pertinence des extraits. Valeur : `RAG_MIN_PARAMS_B` (`models/defaults.py`, 3,0), le seuil que le serveur applique déjà au modèle `rag` par défaut.
- Le front de la Discussion affiche « Vérification peu fiable avec {modèle} » quand la stratégie choisie est `self_rag` et que le modèle choisi est local avec `params_active_b < verify_min_params_b`, ou sans `params_active_b` connu (même règle que `is_weak_judge` pour le juge de l'Arène). Un modèle cloud n'est jamais signalé. La taille vient de `GET /api/models` (déjà publiée), le seuil de ce champ : aucune valeur écrite dans le front (AD-20).
- Aucun autre champ, aucune route nouvelle, aucun code d'erreur nouveau. `409 base_in_use` des routes de suppression et de vidage est inchangé : seul l'écran de la Base n'envoie plus la requête tant qu'un import est visible.
