## Pistes à creuser

- **Contradiction sur les logprobs d'Ollama** : la release v0.12.11 (nov. 2025) annonce les logprobs sur l'API compatible OpenAI, mais la page de compatibilité OpenAI les liste comme non supportés. Même avec des logprobs de sortie, `echo` reste non supporté : la log-vraisemblance sur le prompt, exigée par lm-eval, reste a priori impossible. À trancher avec le code d'Ollama ou un test réel.
- **Inspect passe par `/v1` et non par `/api/chat`** : `num_ctx` doit passer par un Modelfile ; `think`, `format` (schéma JSON natif) et les `options` Ollama ne sont pas exposés. Il faut vérifier si `GenerateConfig` d'Inspect (seed, temperature, `reasoning_effort`, `response_schema`) se traduit correctement vers Ollama, et ce que donne `strict: true` sur les schémas d'outils avec Ollama.
- **Écart de mesure** : un framework qui appelle `/v1` n'a pas la même configuration (num_ctx, think, format) que le script maison sur `/api/chat`. Des scores obtenus des deux côtés ne seraient pas comparables sans alignement. Piste hybride : écrire un provider Inspect personnalisé qui appelle `ollama.chat` (API `ModelAPI` d'Inspect, à vérifier).
- **BFCL sur Ollama** : vérifier si `base_oss_handler` passe par `/v1/completions` avec un template de chat issu d'un tokenizer HF, ce qui imposerait de télécharger un tokenizer et d'appliquer le template côté client, en doublon avec celui d'Ollama. La voie la plus simple serait le BFCL d'inspect_evals (outils natifs, AST) ou un handler FC générique compatible OpenAI. Vérifier la date de la release 2026.3.23 et l'activité du dépôt depuis.
- Confirmer dans le code de lm-eval `--bootstrap_iters` (stderr bootstrap, défaut supposé à 100000), le format exact `samples_<task>_<date>.jsonl` de `--log_samples`, et les champs par échantillon (`doc_id`, `resps`, `filtered_resps`, métriques).
- Confirmer `bootstrap_stderr()` et les stderr groupées (`cluster`) d'Inspect sur la page « Scoring Metrics » (l'URL `scorer-metrics.html` renvoie 404).
- Effort pour un scorer de validation JSON Schema ou d'appel d'outils dans Inspect (`@scorer` + `jsonschema`) : a priori faible, mais non sourcé ce tour.
- Tâches françaises : aucune n'a été trouvée dans inspect_evals. Côté lm-eval, regarder le registre de tâches (`french_bench`, `belebele_fra`, `xnli_fr`, `mgsm_fr`) et leur type de sortie.
